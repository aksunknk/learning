01

単方向データフローと CFG（Control Flow Graph）

▼

CFG としての React ランタイム

React の更新は双方向バインディングではない。情報は一方向にしか流れない。逆方向（DOM → 勝手に State）を許すと、観測不能な状態分岐が増え、障害時の再現グラフが爆発する。

正規パス（簡略 CFG）

User Action
  → Event Handler（同期の意思決定）
  → Side Effect / Async I/O（fetch, WS, timer）
  → setState / dispatch（意図の宣言）
  → Virtual DOM diff（Reconciliation）
  → Commit → Browser Repaint

禁止に近い逆流:
  DOM を読んで State を「推測で」埋める
  Effect 内で無制限に Effect を連鎖させる（観測不能ループ）

SRE 視点

インシデントで追うのは「どのノードで分岐したか」。Handler で分岐したのか、I/O 失敗後の再試行か、Reconciliation の結果 UI が古いのか。単方向制約は障害グラフの辺を減らすための設計制約である。

TypeScript
// Handler は「意図」だけを書く。描画は State の写像に任せる。
function onRetry(dispatch: (a: Action) => void) {
  dispatch({ type: "logs/retry" }); // → reducer/effect が I/O を担う
}
02

TypeScript による Layer 7 防衛（境界モデル）

▼

型は UI 内部の便利機能ではない — L7 の契約壁

FastAPI / OpenAPI がサーバ境界でスキーマを強制するのと同様、ブラウザ側の TypeScript Interface/Type（＋実行時 parse）は不当ペイロードをアプリ核に入れない防衛壁である。any はその壁に穴を開ける。

なぜ any をパージするか

any を付けた瞬間:
- 存在しないフィールド参照がコンパイルを通る
- バックエンドの破壊的変更が「静かに」UI へ侵入する
- 障害時、型が「嘘のドキュメント」になる

境界の正しい受け口:
  unknown（または Zod 等）→ 検証 → 契約型 T
内側（描画・ドメイン）は T だけを信じる。
TypeScript
// FastAPI の response_model に相当する「契約」
type Book = { id: string; title: string; updatedAt: string };

function parseBook(input: unknown): Book {
  if (!input || typeof input !== "object") throw new Error("contract");
  const o = input as Record<string, unknown>;
  if (typeof o.id !== "string" || typeof o.title !== "string") {
    throw new Error("contract");
  }
  return {
    id: o.id,
    title: o.title,
    updatedAt: typeof o.updatedAt === "string" ? o.updatedAt : "",
  };
}

運用メモ

as Book だけのキャストは検証ではない。コンパイルは通っても実行時は壊れる。OpenAPI 生成型があっても、ネットワーク境界では一度 parseする。

03

副作用と再レンダリング最適化

▼

副作用には寿命がある

fetch はコンポーネント寿命より長く生き得る。アンマウント後の setState はリーク警告と Race Condition（遅い応答が新しい画面を上書き）の原因になる。AbortController で I/O 自体を殺すのが正攻法。

TypeScript
useEffect(() => {
  const ac = new AbortController();
  (async () => {
    try {
      const res = await fetch(`/api/logs?q=${q}`, { signal: ac.signal });
      const json: unknown = await res.json();
      setLogs(parseLogList(json));
    } catch (e) {
      if ((e as { name?: string }).name === "AbortError") return;
      setError("fetch_failed");
    }
  })();
  return () => ac.abort();
}, [q]);

状態のエントロピーを下げる

原則:
- State は「可能な限り狭く・ローカルに」
- 親が持つ理由がない値を Context/グローバルへ上げない
- 子の再描画コスト = props 参照の安定性 × 部分木の大きさ

低エントロピー設計:
  List は items だけ受け、選択状態は行コンポーネント内
  サーバキャッシュは専用レイヤ（Query 等）へ追い出し、画面 State を薄くする
04

実戦演習 — 型安全 fetch と loading/error 分離

▼

運用レベル最小骨格

loading / error / data を同一変数に詰めない。UI 分岐が CFG 上の別ノードになるよう、状態機械として分離する。

TypeScript
type Book = { id: string; title: string };

type LoadState =
  | { status: "idle" | "loading" }
  | { status: "error"; message: string }
  | { status: "ready"; books: Book[] };

function parseBooks(input: unknown): Book[] {
  if (!Array.isArray(input)) throw new Error("contract");
  return input.map((row) => {
    if (!row || typeof row !== "object") throw new Error("contract");
    const o = row as Record<string, unknown>;
    if (typeof o.id !== "string" || typeof o.title !== "string") {
      throw new Error("contract");
    }
    return { id: o.id, title: o.title };
  });
}

function BookPanel() {
  const [state, setState] = useState<LoadState>({ status: "idle" });

  useEffect(() => {
    const ac = new AbortController();
    setState({ status: "loading" });
    (async () => {
      try {
        const res = await fetch("/api/books", { signal: ac.signal });
        if (!res.ok) throw new Error(`http_${res.status}`);
        const books = parseBooks(await res.json());
        setState({ status: "ready", books });
      } catch (e) {
        if ((e as { name?: string }).name === "AbortError") return;
        setState({
          status: "error",
          message: e instanceof Error ? e.message : "unknown",
        });
      }
    })();
    return () => ac.abort();
  }, []);

  if (state.status === "loading" || state.status === "idle") {
    return <p className="term">loading…</p>;
  }
  if (state.status === "error") {
    return <p className="term err">ERR {state.message}</p>;
  }
  return (
    <ul className="term">
      {state.books.map((b) => (
        <li key={b.id}>{b.title}</li>
      ))}
    </ul>
  );
}

面談で一言で言うなら

「UI は契約型の写像。I/O は Abort 可能な副作用。状態は局所化し、loading/error/data を混ぜない。」
