06

型の柔軟性（ジェネリクス/Generics）

▼

💡 どんな型でも受け入れつつ、型安全を保つ魔法

ジェネリクスとは？

関数やクラスを作るときに「後から型を決める」仕組みです。配列の定義によく見る Array もジェネリクスの一種です。

TYPESCRIPT 
// 型引数Tを受け取る関数
function getFirstItem(arr: T[]): T | undefined {
  return arr[0];
}

// 使うときに型が決まる
const num = getFirstItem([1, 2, 3]); // num は number 型
const str = getFirstItem(['a', 'b']); // str は string 型

型の合成と防衛（Union型、Intersection型、Interface）

▼

💡 複雑なデータを正確に表現する

Union（ユニオン）とIntersection（インターセクション）

Union型は「A または B」、Intersection型は「A かつ B」を表します。実務ではAPIのステータス表現などで非常に多く使われます。

TYPESCRIPT 
// Union型（パイプライン記号）
type Status = 'loading' | 'success' | 'error';
let currentStatus: Status = 'loading';

// Intersection型（アンパサンド記号）
type User = { id: number; name: string };
type Admin = { privileges: string[] };

type AdminUser = User & Admin; // 両方のプロパティを持つ
08

よくあるエラーとアンチパターン

▼

💡 TypeScriptを使う意味をなくしてしまう書き方

any型への逃避

型エラーが解決できないとき、とりあえず any を使ってしまうのは最悪のアンチパターンです。型チェックが完全に無効になり、バグの温床になります。

TYPESCRIPT 
// ❌ anyの濫用
function processData(data: any) {
  return data.toUpperCase(); // 実行時にdataが数値ならクラッシュする
}

// ✅ unknown型を使って安全にチェックする
function safeProcess(data: unknown) {
  if (typeof data === 'string') {
    return data.toUpperCase();
  }
}

Object is possibly null

APIのレスポンスやDOMの取得など、「値が存在しないかもしれない（null/undefined）」ケースでそのままプロパティにアクセスしようとすると怒られます。

TYPESCRIPT 
// ❌ エラーになる
// const el = document.getElementById('my-btn');
// el.click(); // Object is possibly 'null'

// ✅ オプショナルチェーン（?.）を使う
document.getElementById('my-btn')?.click();

InterfaceによるAPIスキーマの定義

FastAPIのPydanticモデル（Task）と全く同じ構造をTypeScriptのInterfaceで定義することで、通信データを安全に扱えます。

TYPESCRIPT 
interface Task {
  id: number;
  title: string;
  completed: boolean;
}

// fetch通信にも型をつける
async function fetchTasks(): Promise {
  const response = await fetch('http://localhost:8000/tasks');
  if (!response.ok) {
    throw new Error('Network response was not ok');
  }
  return await response.json();
}
